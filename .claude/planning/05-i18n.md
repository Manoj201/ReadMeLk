# 05 — Internationalization (Sinhala / English)

## Library & wiring

- `react-i18next` + `i18next` + `i18next-browser-languagedetector`.
- Detection order: `localStorage` key `readme.lang` → `navigator` → fallback `en`.
  `caches: ['localStorage']`.
- The active language also lives in `uiStore.language` so non-React code and the store can
  read it; `LanguageToggle` calls `i18n.changeLanguage(next)` **and** `setLanguage(next)`,
  kept in sync by one subscription.
- On language change: set `document.documentElement.lang` (`si` / `en`) and `dir="ltr"`
  (both are LTR), and swap the font class on `<body>` (see Fonts).
- `fallbackLng: { si: ['en'], default: ['en'] }`. In dev, `saveMissing: true` +
  `missingKeyHandler` logs to console so gaps are visible.

## Two distinct kinds of text

### 1. UI chrome → translation keys

Files: `src/locales/en/<ns>.json` and `src/locales/si/<ns>.json`.

Namespaces: `common`, `auth`, `book`, `author`, `review`, `home`, `admin`.

Key convention: `screen.element` within the namespace file, e.g.
`review:form.ratingLabel`, `home:bestReviewed.title`, `common:actions.save`.

Rules:
- No hardcoded user-facing strings in components — ESLint `i18next/no-literal-string`
  (scoped to `src/**`, JSX text + common attributes) enforces this; add to the review
  checklist too.
- Pluralization via i18next `_one` / `_other` suffixes (both languages).
- Interpolation with named vars only: `t('book:reviews.count', { count })`.
- Keep keys sorted; one namespace per feature area so ownership is obvious.

### 2. User-generated content → bilingual fields, never machine-translated

- Structured content authors enter twice: `nameEn`/`nameSi`, `bioEn`/`bioSi`,
  `titleEn`/`titleSi`, `descriptionEn`/`descriptionSi`. A `useLocalizedField(obj, base)`
  helper returns the active-language value, falling back to the other language and
  reporting which one it returned so the UI can show a "සිංහල" / "English" chip.
- Free-text reviews are stored once with `bodyLang`. They are always shown as written; if
  `bodyLang !== activeLanguage` a small language chip is shown (no translation offered).
- At least one language is required on create; the second can be added by editing later.
- Empty-string (not `null`) means "not provided" for these fields.

## Fonts

- **Sinhala:** *Noto Sans Sinhala* (body) and *Noto Serif Sinhala* (headings), self-hosted
  in `public/fonts/` and declared with `@font-face` + `font-display: swap`. Subset to the
  Sinhala + Latin ranges to keep files small.
- **Latin:** *Inter* (body) + a humanist serif for display headings (e.g. *Frank Ruhl* or
  *Source Serif*), self-hosted, `font-display: swap`.
- CSS custom properties: `--font-sinhala-sans`, `--font-sinhala-serif`, `--font-latin-sans`,
  `--font-latin-serif`. `body.lang-si` uses the Sinhala stacks first; `body.lang-en` uses
  the Latin stacks first; every stack lists the other script's font as a fallback so mixed
  strings render.
- **Sinhala needs more vertical space:** `body.lang-si` bumps base `line-height` (~1.7 vs
  ~1.55) and slightly increases heading line-height; documented in
  [06-design-system.md](06-design-system.md) type scale.
- Never load fonts from a third-party CDN (privacy + offline + Vercel edge).

## Formatting

- `lib/format.ts` binds `Intl` to the active locale: `si-LK` or `en-LK`.
  - `formatDate(ts)` → `Intl.DateTimeFormat(locale, { dateStyle: 'medium' })`.
  - `formatNumber(n)`, `formatRating(n)` → one decimal, locale digits.
- Relative times ("2 days ago") via `Intl.RelativeTimeFormat` in the active locale.

## Translation coverage & QA

- A script (`yarn i18n:check`, added in M6) diffs `en` vs `si` key sets per namespace and
  fails on any key present in one but not the other.
- Manual pass in M6: walk every screen in `si` and confirm no English leakage, no clipped
  layout, correct fallback chips.
